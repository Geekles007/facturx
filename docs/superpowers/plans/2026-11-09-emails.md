# Les e-mails de facturx — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** des e-mails du compte aux couleurs de facturx, en français ou en anglais, et une relance habillée au nom de l'entreprise, versionnés dans le dépôt et déployés par le workflow.

**Architecture :** un module partagé, `site-src/shared/courriel.ts`, dessine le cadre HTML et formate montants et dates ; `relancer` l'emploie par `_vendor/shared/`, le Studio pour le formatage. `site-src/courriels/compte.ts` écrit les cinq modèles Go de Supabase Auth ; `pnpm emails:construire` les génère dans `supabase/templates/`, que la pile locale lit par `config.toml` et que `scripts/emails-deployer.mjs` pose en production par l'API de gestion. La langue du compte vit dans `user_metadata.langue`.

**Tech Stack :** TypeScript, Preact, esbuild, Vitest ; Deno (Edge Functions, `deno test`) ; Supabase Auth (modèles Go `text/template`), Mailpit (pile locale), API de gestion de Supabase ; GitHub Actions.

**Spec :** [docs/superpowers/specs/2026-11-09-emails-design.md](../specs/2026-11-09-emails-design.md)

## Global Constraints

- Messages de commit en français, dans le style du dépôt (`git log`) ; **aucune mention de Claude ni d'Anthropic**, ni trailer, ni « Generated with ». `git add` par chemin ; jamais de `git stash` nu.
- Commentaires en français, à la densité du code voisin ; formatage Biome (2 espaces, guillemets simples, 100 colonnes). `pnpm lint` passe à chaque commit.
- Les modules de `site-src/shared/` n'ont **aucun import relatif** (Deno ne résout pas `./x.js` vers `./x.ts`).
- Jamais `supabase config push`, `supabase db reset`, `supabase start` ni `supabase stop` hors de la CI : la pile locale de l'utilisateur est à lui.
- Les e-mails ne chargent **aucune ressource distante** (image, police, feuille de style) et n'écrivent **aucune durée de validité**.
- Les modèles du compte n'affichent que `{{ .ConfirmationURL }}`, `{{ .Email }}`, `{{ .NewEmail }}`, `{{ .Token }}` ; `.Data` n'apparaît que dans la comparaison `eq (printf "%v" .Data.langue) "en"`.
- Textes des e-mails : apostrophe typographique `’` ; en français, espace insécable (U+00A0) avant `?`, `:`, `;` et `!`, comme sur le site.
- La réponse de l'API de gestion n'est **jamais** affichée ni écrite : elle contient la configuration d'authentification entière, mot de passe SMTP compris.
- Tout libellé ajouté au Studio existe en français et en anglais dans `site-src/studio/i18n.ts`.
- Langues : `fr` (locale `fr-FR`) et `en` (locale `en-GB`), le français par défaut.

## Review Focus

1. **Un modèle Go qui échoue** (à l'analyse ou à l'exécution) : Supabase n'envoie rien et l'inscription ne se confirme plus. Une `langue` absente, numérique ou objet doit donner le français, jamais une erreur — Task 5 le prouve contre la pile, pour les cinq modèles.
2. **Un nom d'entreprise hostile** (`<`, `&`, guillemets, caractères de sens d'écriture) dans l'en-tête et le pied de la relance : échappé partout, HTML comme texte — Task 6.
3. **Une facture en USD**, lue en anglais : montant formaté `US$1,250.00` par `en-GB`, sans conversion — Task 1 et Task 6.
4. **Un Studio resté ouvert d'avant ce chantier** : sa demande de relance n'a pas `langue`, le serveur prend celle de la facture puis le français — Task 6.
5. **Le déploiement qui écrirait un secret dans le journal public** : le script n'affiche que des codes HTTP et des noms de clés, même quand la réponse en contient — Task 8.
