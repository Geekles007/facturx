Trois appels

1Décrire, puis calculer

Montants en entiers (centimes, points de base) — jamais de flottant. Les totaux sont calculés explicitement, puis vérifiés : le SDK ne corrige jamais en silence.

import { cents, computeTotals, percent, quantity, unitPrice, assertValidInvoice } from 'facturx-sdk';

const draft = {
  id: 'F-2026-0001', issueDate: '2026-09-11', typeCode: '380', currency: 'EUR',
  operationCategory: 'services',                      // nature de l'opération (réforme)
  seller: { name: 'Atelier Exemple SAS', siren: '443061841', vatId: 'FR64443061841', address: { /* … */ countryCode: 'FR' } },
  buyer:  { name: 'Client Démo SARL', siren: '732829320', electronicAddress: { value: '732829320', scheme: '0225' }, address: { /* … */ } },
  lines: [{ id: '1', name: 'Conseil', quantity: quantity(20000), unitCode: 'DAY', unitPrice: unitPrice(8000000),
            netAmount: cents(160000), tax: { category: 'S', rate: percent('20') } }],
  paymentTerms: { dueDate: '2026-10-11', latePenaltyRate: percent('10'), recoveryIndemnity: cents(4000), earlyPaymentDiscount: 'none' },
};
const invoice = assertValidInvoice({ ...draft, ...computeTotals(draft) });
// FacturXValidationError { issues: [{ code: 'BR-CO-15', path: 'totals.taxInclusiveAmount', … }] } sinon

2Émettre

Le XML CII est produit par templating typé, dans l'ordre du XSD, puis embarqué dans votre PDF (déjà PDF/A) avec les métadonnées XMP Factur-X.

import { toCiiXml } from 'facturx-sdk';
import { embedFacturX } from 'facturx-sdk/pdf';

const xml = toCiiXml(invoice);                           // conforme XSD + schematrons
const pdfA3 = await embedFacturX(pdfBytes, { invoice });   // PDF/A-3, validé veraPDF

3Recevoir

Dès le 1er septembre 2026, toute entreprise doit savoir lire ce qu'elle reçoit. Une facture incohérente est signalée avec le chemin exact de chaque anomalie — jamais intégrée telle quelle.

import { fromCiiXml, readCiiGuideline } from 'facturx-sdk';
import { extractInvoice } from 'facturx-sdk/pdf';

const received = await extractInvoice(pdfBytes);          // { invoice, xml, conformanceLevel } | undefined
const invoice  = fromCiiXml(xmlString);                  // validée, ou FacturXParseError { code, path }
const { guidelineId } = readCiiGuideline(xmlString);     // router sans tout lire

Où le SDK se place dans la réforme

La facturation électronique impose de recevoir les factures structurées dès le 1er septembre 2026 pour toutes les entreprises, et de les émettre selon la taille, via une plateforme agréée. Le SDK est la brique format et conformité ; la plateforme est la brique transport.

  1. 1er sept. 2026Réception pour toutes les entreprises · émission pour les grandes entreprises et ETI
  2. 1er sept. 2027Émission pour les PME, TPE et micro-entreprises

Le SDK fait

  • XML CII EN 16931 et PDF/A-3 Factur-X
  • Validation EN 16931 + règles françaises, erreurs typées avec chemin
  • Lecture de tout profil, ré-émission fidèle
  • Mentions de la réforme : SIREN acheteur, nature de l'opération, TVA sur les débits, adresse 0225
  • Acomptes, avoirs, pièces jointes, notes légales générées
  • Limites de taille, pas de DTD : entrées non fiables bienvenues

Le SDK ne fait pas

  • Envoyer à une plateforme agréée, statuts, e-reporting
  • Convertir un PDF quelconque en PDF/A
  • UBL, autres profils Factur-X en écriture

Tout est écrit noir sur blanc dans le guide de la réforme et le journal des décisions.
