Trois appels, et la conformité n'est plus votre problème.

Montants en entiers, totaux calculés puis vérifiés, erreurs typées avec le chemin exact du champ. Le SDK ne corrige jamais en silence.

import { cents, computeTotals, percent, quantity, unitPrice, assertValidInvoice } from 'facturx-sdk';

const draft = {
  id: 'F-2026-0001', issueDate: '2026-09-11', typeCode: '380', currency: 'EUR',
  operationCategory: 'services',                       // nature de l'opération (réforme)
  seller: { name: 'Atelier Exemple SAS', siren: '443061841', vatId: 'FR64443061841',
            address: { postCode: '75011', city: 'Paris', countryCode: 'FR' } },
  buyer:  { name: 'Client Démo SARL', siren: '732829320',
            electronicAddress: { value: '732829320', scheme: '0225' },   // routage plateforme
            address: { postCode: '69002', city: 'Lyon', countryCode: 'FR' } },
  delivery: { date: '2026-09-10' },
  lines: [{ id: '1', name: 'Conseil', quantity: quantity(20000), unitCode: 'DAY',
            unitPrice: unitPrice(8000000), netAmount: cents(160000),
            tax: { category: 'S', rate: percent('20') } }],
  paymentTerms: { dueDate: '2026-10-11', latePenaltyRate: percent('10'),
                  recoveryIndemnity: cents(4000), earlyPaymentDiscount: 'none' },
};

const invoice = assertValidInvoice({ ...draft, ...computeTotals(draft) });
// sinon : FacturXValidationError { issues: [{ code: 'BR-CO-15', path: 'totals.taxInclusiveAmount', … }] }
import { toCiiXml } from 'facturx-sdk';
import { embedFacturX } from 'facturx-sdk/pdf';

// XML CII EN 16931 — templating typé, ordre du XSD garanti, conforme aux schematrons
const xml = toCiiXml(invoice);

// Votre PDF (déjà PDF/A) + le XML → PDF/A-3 Factur-X, validé par veraPDF

  outputIntent: { iccProfile: srgb },   // optionnel
});
import { fromCiiXml, readCiiGuideline } from 'facturx-sdk';
import { extractInvoice } from 'facturx-sdk/pdf';

// PDF reçu → facture typée, validée (ou undefined sans Factur-X)
const received = await extractInvoice(pdfBytes);

// XML reçu → facture typée ; FacturXParseError { code, path } si illisible

Conçu pour ne rien laisser au hasard.

Jamais d'arrondi silencieux

Centimes, quantités et prix en entiers, produits en bigint, arrondi commercial unique. Les totaux que vous fournissez sont vérifiés — un TTC qui ne colle pas est une erreur nommée, pas une valeur corrigée à votre place.

Erreurs typées, chemin exact

BR-CO-15 @ totals.taxInclusiveAmount. Codes officiels EN 16931 et AFNOR, prêts pour votre formulaire.

Règles françaises officielles

22 règles BR-FR de la norme XP Z12-012 : SIREN, cadre de facturation, notes légales, adresses 0225, TVA sur les débits.

Les trois syntaxes du socle

Factur-X, CII nu et UBL : tout profil, tout préfixe, pièces jointes, acomptes, avoirs. Une même facture lue en CII et en UBL rend le même objet. Éprouvé sur 30 factures d'autres outils, ré-émises conformes.

Statuts du cycle de vie

Les quatre statuts transmissibles au portail public — l'annexe officielle n'en connaît pas d'autres pour une facture —, les 40 motifs de refus normalisés, et le message CDV écrit et relu, validé contre le schéma CDAR d'UN/CEFACT.

Sécurité par défaut

Pas de DTD ni d'entité externe, profondeur et tailles bornées, aucune exécution de contenu. SECURITY.md

Edge, serverless, navigateur

Aucune API Node dans l'entrée principale ; pdf-lib uniquement dans facturx-sdk/pdf. Un handler Request → Response suffit pour Next.js, Hono ou Cloudflare Workers — l'exemple est dans le dépôt.

Où le SDK se place dans la réforme

Recevoir des factures structurées devient obligatoire pour toutes les entreprises, puis les émettre selon la taille, via une plateforme agréée. Le SDK est la brique format et conformité ; la plateforme, la brique transport.
