Ce que contrôle cet outil

Quatre juges

Le SDK vérifie le modèle, l'arithmétique en centimes et les règles françaises, avec le chemin exact du champ fautif. Les trois schematrons officiels rendent leur verdict sur le XML tel quel, avec leurs propres codes de règle.

Trois tolérances assumées

Trois avertissements sont signalés comme tolérés, jamais masqués : ils opposent une règle PEPPOL ou CII à une exigence de la norme française. La raison est affichée avec chacun.

Ce qui manque encore

Le contrôle PDF/A-3 par veraPDF réclame Java, donc un serveur : il n'est pas exécuté ici. Le SDK le passe en intégration continue sur chaque version publiée.

Une facture d'exemple à récupérer

Le PDF Factur-X d'exemple est produit par le SDK lui-même : profil EN 16931, mentions françaises, PDF/A-3b vérifié par veraPDF. Son jumeau volontairement fautif porte quatre défauts courants, listés sur la page même du PDF, pour vérifier qu'une chaîne de réception rejette ce qu'elle doit rejeter.

Mêmes règles qu'en intégration continue

Les jeux de règles sont ceux du dépôt mustangproject à un commit épinglé, compilés puis exécutés par Saxon-JS — exactement ce qui juge le SDK à chaque commit.
